# Localisation

How Aximar shows its text, Maxima's messages and the help in the user's
language: where each piece of text comes from, where its translations come
from, how they reach the window, who keeps them up to date, and what can
break. It starts from [#44](https://github.com/cmsd2/aximar/issues/44), a
request for Spanish for a student pilot.

## Principles

- **Maxima runs in English.** Aximar reads Maxima's messages to tell when
  an evaluation failed, so the language between Maxima and Aximar never
  changes. Translation happens where Aximar draws text.
- **Translations come from whoever owns the text.** Aximar translates its
  own text. Maxima's messages and manual come from Maxima's translators,
  and Aximar reads them from the installed Maxima instead of copying them.
- **gettext `.po` files throughout.** Maxima's translations are `.po`
  files, so Aximar's are too: one format and one set of tools for
  translators working on either.
- **The repository is the source of truth.** Catalogs live in git, and any
  tool, from a desktop editor to Weblate, works on those files.
- **A missing translation falls back to English, one message at a time.**
  A partly translated language is still useful.
- **The language is an Aximar setting**, defaulting to the system's.
  Aximar never passes it to Maxima's environment.
- **Results and user output stay as written.** Aximar translates text about
  a computation, never the computation: `print` output, results and
  function names stay as Maxima gives them.

### Where a translator works

| | Where | Covers | Reaches users with |
|---|---|---|---|
| 1 | Aximar's catalog, `locales/<lang>.po` in this repository | Everything Aximar draws, plus Maxima's syntax errors and common warnings | The next Aximar release |

A new language needs only the first. The other two are fixes to Maxima's
own translations, which go upstream. Spanish starts with Maxima's 79% of
messages and 85% of its manual already done.

## Data flow

### A failed cell

```
cell input
  │
  ▼
Maxima, started with LANGUAGE=en                       (process.rs)
  │  merror("~:@M: wrong number of arguments.", diff)
  │  └─ errormsg(), wrapped by ax_messages.lisp
  │       ├─ prints  diff: wrong number of arguments.
  │       └─ looks the pattern up for ax__language = "es",
  │          formats it, prints
  │          __AXIMAR_MSG__diff: número de argumentos equivocados.__AXIMAR_MSG_END__
  ▼
stdout and stderr lines                                (MaximaProcess)
  │
  ▼
legacy parser                                          (legacy/parser.rs)
  ├─ English markers   → is_error, error
  ├─ errors.rs         → error_info, as message descriptions
  └─ tagged line       → error_translated
  ▼
CellOutput, synced to the window
  ▼
EnhancedErrorOutput: Aximar's explanation translated by Lingui, Maxima's
message in Spanish, and "Show original" for the English
```

The tagged line comes out at error time, before Maxima shows any prompt,
so this works at the top level, inside `errcatch` and in the debugger. A
query after the error would only work at the normal prompt.

### The language

```
Aximar setting (default: the system language, if a catalog covers it)
  ├─ window:   "language-changed" to every window: i18n.load + i18n.activate
  ├─ menus:    Rust rebuilds the menu from the same .po (embedded)
  ├─ Maxima:   the registry's language; each session sets ax__language
  │            with a :lisp line before its next cell
  ├─ MCP:      English, IDs and parameters; docs tools take a language
  └─ help:     the docs panel's language (same as the app by default),
               then English, symbol by symbol
```

### Catalogs, from source to release

```
React source: t`...`, <Trans>        Rust source: msg!(...), msg_ctx!(...)
        │ lingui extract-template           │ xgettext --language=Rust --keyword=msg!
        ▼                                   ▼
  window.pot ────────── msgcat ────────── rust.pot
                          │
                          ▼
                 locales/messages.pot  (committed; CI checks it's current)
                          │ msgmerge --previous
                          │ msgmerge --compendium <Maxima>/locale/es.po (new strings)
                          ▼
                 locales/es.po  ◀── translators (Poedit, Lokalize, OmegaT, Weblate)
                          │
             ┌────────────┴─────────────┐
             ▼                          ▼
   Lingui Vite plugin            include_str! + rspolib
   (window, loaded per language)  (menus, in src-tauri)
```

Maxima's message catalogs and manual aren't part of Aximar's build: Maxima
installs its catalogs and reads them at run time, and catalog-gen reads the
manual from a Maxima source checkout.

## Technical design

### English between Maxima and Aximar

Maxima picks its language from the first of `LANGUAGE`, `LC_ALL`,
`LC_MESSAGES` and `LANG` that's set (`setlocale` in Maxima's
`src/intl.lisp`), using only the first two letters. Aximar sets
`LANGUAGE=en` on the local, Docker and WSL launches (`MAXIMA_LANGUAGE` in
`process.rs`, [#107](https://github.com/cmsd2/aximar/pull/107)).

Aximar sets only `LANGUAGE` on the local launch: changing `LC_ALL` would
also change the C library's locale, and with it the character set SBCL
uses for UTF-8. Docker and WSL also set `LANG` and `LC_ALL` to
`en_US.UTF-8`, as before.

Without the pin, a Spanish system language broke Aximar:
- a failed cell came back as the result before it;
- Run All went past errors;
- the debugger hung on a syntax error.

### Maxima's runtime errors: `ax_messages.lisp`

`merror` stores each error in `$error` as its message pattern and
arguments, such as `("~:@M: wrong number of arguments." diff)`. Under
English, the pattern is exactly the msgid in Maxima's catalog. Every
branch of `merror` prints through `errormsg()`.

The wrapper:
1. calls the original `errormsg()`, so the English message prints as
   before;
2. looks the pattern up with Maxima's own `intl:dgettext`, with
   `intl::*locale*` bound to `ax__language` for that one lookup;
3. if the catalog has a translation, calls the original `errormsg()` again
   with the translated pattern, capturing its output, so Maxima formats
   the arguments as usual;
4. prints the result as one tagged line, newlines as `\n` and backslashes
   doubled.

It prints nothing when `ax__language` is empty, when the catalog has no
translation, or when anything in steps 2 to 4 fails.

Aximar sends the file at session start as one `:lisp` line, before the
plotting init's evaluation, which reads the line's reply. Sent with no
evaluation after it, the reply leaks into the first cell's output.

The parser lifts the tagged line into `error_translated` and keeps it only
when the evaluation failed. `errcatch` prints the messages of errors it
catches, but those cells succeed. When one cell prints several messages,
the last belongs to the error that stopped it.

### Aximar's catalog

**Format.** One gettext `.po` file per language in `locales/`, with the
template `locales/messages.pot`. Each entry carries:
- the English text as its msgid, so editors show translators the source
  directly, as Maxima's own `es.po` does;
- `msgctxt` where one English word means two things ("Open" as a verb in
  the File menu);
- a `#.` comment saying where the string appears, what it does, and what
  its placeholders hold;
- `#:` references to the source lines;
- optional flags in comments, in Weblate's syntax, such as
  `#. max-length:24` for menu items and `max-length:16` for the
  Settings window's sidebar labels, which sit in a 168px column.

Plurals use gettext's own `msgid_plural` and `msgstr[n]` entries, so
editors show their plural form editors.

**Placeholders** are named, in braces: `{func}`, `{count}`. That form is
valid in Lingui's messages, in Rust format strings, and to `msgfmt -c`, so
translators see one style everywhere. Rust-side strings don't use ICU
plurals or selects, and hold no literal braces: Rust writes one as `{{`
and ICU as `'{'`, so one translation can't serve both.

**The window** uses Lingui (`@lingui/core`, `@lingui/react`, and the Vite
plugin, with the `po-gettext` formatter so plurals stay native gettext):

```tsx
t({ message: "Show original", comment: "Button under a translated Maxima error; shows the English text" })
t({ message: "Open", context: "verb, File menu" })
```

`comment` becomes `#.` and `context` becomes `msgctxt`.

**Rust** marks strings with a `msg!` macro (and `msg_ctx!` for context)
that builds a `Message` (`aximar_core::message`) rather than a finished
string: the context as `id`, the English `template`, its `params`, and the
English `text` rendered from them. Notes for translators go in a source
comment starting `i18n:`, which `xgettext` copies into the `.po`:

```rust
// i18n: Title of the explanation for 1/0
msg_ctx!("error.division_by_zero.title", "Division by zero")
// i18n: func is a Maxima function name; n is a number of arguments
msg!("{func} expects {n} arguments", func = name, n = count)
// i18n: verb, in the File menu
msg_ctx!("File menu", "Open")
```

`xgettext` reads only source comments, not macro arguments, so the note
can't be an argument of `msg!`. It takes the comment on the lines just
above the English text, so in a call that rustfmt splits over several
lines the note goes inside, after the context:

```rust
msg_ctx!(
    "error.syntax_missing.explanation",
    // i18n: delimiter is a closing bracket, such as ) or ]
    "A closing {delimiter} is missing.",
    delimiter = delimiter
)
``` The macros render `text` with `format!`
inside a function item, so a placeholder without a parameter, or a
parameter without a placeholder, fails to compile; a local variable can't
stand in for a missing parameter. Extraction reads only each crate's
`src/`, so tests in `tests/` can call the macros without their strings
reaching the catalog.

- `aximar-core` sends descriptions to the window, which translates them
  with Lingui. `errors.rs`, the suggestion chips and the `asksign` notice
  change this way.
- `src-tauri` translates the menus itself from the same `.po`, embedded
  with `include_str!` (or read from disk in preview builds) and parsed
  with `rspolib`. If a Rust-side string ever needs a plural, the `tr`
  crate's `po-translator` evaluates the `Plural-Forms` header over
  `rspolib`.

**Extraction and merging** follow gettext's usual flow, in
`scripts/i18n-extract`:
1. `lingui extract-template` extracts the window's strings, and
   `xgettext --language=Rust --keyword='msg!' --keyword='msg_ctx!:1c,2'
   --add-comments=i18n:` extracts Rust's. GNU gettext has extracted Rust
   since 0.24; Homebrew and Alpine 3.24 have 1.0, but Ubuntu 26.04 has
   only 0.23. It marks strings with placeholders `rust-format`, so
   `msgfmt -c` checks their translations.
2. `msgcat` joins the two into `locales/messages.pot`, under a header
   with `Language: en`: Lingui reads the template as the English catalog,
   and its parser needs a language.
3. `msgmerge --previous` updates each language. A string whose English
   changed becomes fuzzy, with the old English kept as `#|`, so the
   translator sees what changed.

`scripts/i18n-extract --check` changes nothing and fails, with a diff, if
the template or a catalog is out of date. References carry file names
without line numbers, so moving code doesn't change the template.

When a language is added, `msgmerge --compendium` with Maxima's catalog
for it suggests Maxima's existing translations, marked fuzzy. For Spanish
it found none: Maxima's catalog holds its error messages, which share no
text with Aximar's. The glossary carries Maxima's terms instead.

Fuzzy entries never show: the window's catalog format
(`src/lib/po-format.ts`) and the menus' (`src-tauri/src/i18n.rs`) treat
them as untranslated until a translator clears the mark.

**Curated Maxima text.** Maxima's syntax errors and common warnings go in
the same catalog, with Maxima's English pattern as the msgid and a comment
saying so. The parser matches the English and looks the pattern up.

### Loading and switching

- **The setting** is `language` in the app config: `null` until the user
  picks one in Settings, which follows the system language
  (`sys-locale`), matched to the catalogs with `fluent-langneg`, so
  `es_CO` takes `es` and a language without a catalog takes English. The
  languages are the `locales/*.po` files at build time, but `pseudo`.
- **The window:** the Vite plugin compiles each `.po` on import, and the
  window loads a language only when it's chosen (`activateLanguage` in
  `src/lib/i18n.ts`). Switching is `i18n.load` and `i18n.activate`; React
  re-renders without a restart. A change sends `language-changed` to every
  window.
- **Aximar's explanations:** the core sends each in English with its
  template, context and parameters; `errorText` (`src/lib/messages.ts`)
  looks the template up under its context and fills in the parameters, or
  shows the English when the catalog lacks it. A test renders every Rust
  message through that lookup.
- **Menus:** `src-tauri/build.rs` embeds each `.po`; `menu.rs` builds the
  menu bar through `Translations` (`src-tauri/src/i18n.rs`, over
  `rspolib`, skipping fuzzy entries) and `app.set_menu` replaces it on a
  switch.
- **Maxima:** the notebook registry holds the language, shared by every
  notebook. A session sets `ax__language` when it starts and, if the
  language changed, before its next cell, with
  `:lisp (progn (setq $ax__language "es") (values))`. As Lisp that
  returns nothing, it prints nothing and leaves `%` and the input line
  numbers alone.
- **MCP** results stay English. `get_cell` leaves out Maxima's
  translated message, which is for the window. The documentation tools
  answer in a language a client asks for (see Help).
- **Help:** `catalog-gen summaries --lang es` makes
  `core-doc-summaries.es.json` from Maxima's Spanish manual: it runs
  `mxpm doc generate-core-docs --lang es`, which builds the
  `maxima-core-docs-es` pack from `doc/info/es`, and keeps each symbol's
  summary (2317 of the English index's 2698). The core
  embeds it (`catalog/summaries.rs`) and indexes both languages'
  summaries for search, so a Spanish phrase finds its symbol. How the
  window, MCP and the language server use them is under Help.
- **Preview from disk:** pre-release builds have "Load translation
  file..." in Settings. The backend (`commands/translation_preview.rs`)
  reads the `.po` with `rspolib`, rebuilds the menus from it, and checks
  the file twice a second; on each save it sends the translated entries to
  every window, which compiles them (`src/lib/translation-preview.ts`)
  over English and shows them in the file's language. Plurals show for
  languages with one form for 1 and another for the rest; others show
  English for plural entries.
- **Pre-release builds** are debug builds, and release builds made with
  `VITE_AXIMAR_TRANSLATOR_TOOLS=1 npm run tauri build -- --features
  translator-tools`. Other builds have neither the preview nor
  show-sources: the window leaves them out, and the backend's preview
  commands refuse.

### Context for translators

- **In the file:** comments, context, source references and length flags,
  as above.
- **Gallery:** Storybook (`npm run storybook`) holds a story for each
  state a translator needs to see: every error explanation and note the
  core gives (fixtures that `tests/maxima_messages.rs` generates), cells,
  plots, the panels, the editor's popups, the whole window, the trust
  banner, the toolbar and tabs, Settings and the other dialogs.
  Tauri's calls are mocked (`.storybook/tauri-mock.ts`, with a small
  function catalog in `.storybook/catalog-fixture.ts`), and a toolbar
  switches the language, the pseudo-locale included.  A story whose
  content arrives late (a docs page, a completion list, a chart) renders
  `WaitFor` from `src/stories/wait.tsx`, and the screenshot run waits
  until it clears.
  `npm run i18n:gallery` builds it and runs `scripts/i18n-gallery.mjs`,
  which screenshots every story in English, Spanish and the pseudo-locale
  with Playwright, then renders each story with its strings tagged and
  writes which stories show which strings to `locales/screens.json`.
  `scripts/i18n-extract` turns that into comments
  (`#. screen: dialogs--settings`). CI's `gallery` job uploads the
  Storybook with its screenshots (`gallery/index.html`) as the
  `translator-gallery` artifact.
- **Show sources:** in pre-release builds, a Settings checkbox; then
  holding Alt and pointing at text shows each string in it: its English,
  context, notes and source file, from the template. While it's on, each
  translated string ends with its ID in invisible characters
  (`src/lib/show-sources.ts`); the mode is a private-use alias of the
  language (`es-x-src`), so turning it on re-renders the window.
- **Pseudo-locale:** Lingui's built-in pseudo-locale shows text that never
  went through the catalog, and where longer translations overflow. It's
  for developers, before a translator starts:
  `VITE_AXIMAR_LOCALE=pseudo npm run tauri dev` shows catalog text
  accented (`Śĥōŵ ōŕĩĝĩńàĺ`), so anything still plain English isn't in the
  catalog. Release builds leave it out.
  With every component moved into the catalog, the only plain English in
  the pseudo-locale is meant to be there: the notebook's own text and
  results, Maxima's messages, log entries, product names (Docker, WSL,
  Claude Code), keyboard shortcuts, Plotly's own toolbar, and the
  suggestion chips, which aximar-core still sends as English text.
- **Glossary:** `locales/glossary.tbx`, Maxima's own Spanish for its terms
  (argumento, función, matriz, no definido), Aximar's (celda, cuaderno,
  sesión), and the names that stay in English. OmegaT and Lokalize load
  it.
- **Translator guide:** `locales/README.md`: tone (tú or usted),
  capitalisation, decimal points in code examples, and how to use the
  preview build.

### Rust crates and tools

| Need | Crate or tool | Notes |
|---|---|---|
| Read `.po` and `.mo` | `rspolib` | Handles `msgctxt`, plurals, previous msgids and comments. Doesn't evaluate `Plural-Forms`. Give it a path or the text: 0.1.2 parses bytes as an empty catalog. |
| Plural rules | `tr` with `po-translator` | Its own `Plural-Forms` parser, over `rspolib` |
| Extract Rust strings | GNU `xgettext` 0.24 or later | `--keyword='msg!'` finds our macro, and `i18n:` comments become `#.` |
| Check and merge | GNU `msgfmt -c`, `msgmerge`, `msgcat` | `msgfmt -c` checks Rust format strings too |
| Pick the language | `sys-locale`, `fluent-langneg` | |

Avoided:
- `gettext` (pure Rust): last released in 2019, with no fallback from
  `es_CO` to `es`.
- `gettext-rs`: binds to the system's libintl, which complicates packaging
  on Windows and macOS.
- `xtr` and `cargo-i18n`: little used, and they only see `tr!` calls.

What Aximar writes itself:
- the `msg!` macro and its description type;
- the extraction script that joins the two templates;
- the placeholder and length test;
- the preview-build loader.

### Help

The help has a language of its own: the docs panel's menu offers "Same as
Aximar", the default, and each language with documentation. The choice is
the config's `docs_language` (null follows the app's language).

**Where it comes from.** A doc index names its language in a `language`
field (English when it has none), and a translated index sits beside the
English one as `<stem>-doc-index.<lang>.json`. Aximar embeds the Spanish
summaries: `catalog-gen summaries --lang <lang>` reads
`doc/info/<lang>/maxima.texi` through mxpm and writes
`core-doc-summaries.<lang>.json`, the summaries alone. Full documentation
in a language comes from a package, such as `maxima-core-docs-es` once
core-docs publishes it.

**How a symbol is looked up.** The catalog answers in a chain, the help's
language then English, one symbol at a time: a full translation where one
is installed, else the English entry with the summary from the first
language that has one. Each answer says which language each part is in.
Search matches every language, since students may search in either, and
shows results in the help's language.

**What the reader sees.** The docs panel says what it's showing:
- a translated summary above documentation in another language, with a
  note naming that language;
- a note when a function has nothing in the help's language;
- a warning when a translation's signatures differ from the English, so
  it may describe an older version, with the English signatures;
- when the help's language has no full documentation installed, the
  `mxpm install` command for its package, or that there isn't one yet.

The docs panel's stories show each of these in every language.

**Other front ends.** The same lookups serve MCP and the language server:
- MCP's `get_function_docs` and `search_functions` take an optional
  `language`, such as `es`. A result names the language of each text:
  `language` for `full_docs`, `description_language` for `description`,
  and `language` on each search result. `fallback_from` says the function
  has nothing in the language asked for, and `stale` with
  `english_signatures` says a translation may be out of date. Without
  `language` the tools answer in English, as they did before.
- maxima-lsp reads `locale` from `initialize` (VS Code sends its display
  language) and answers hover, completion and signature help in it. A
  regional locale such as `es-ES` falls back to `es`, then English. Hover
  puts a translated summary above documentation in another language.

## Checks in CI

The `i18n` job runs in an Alpine container, for its GNU gettext:
- `scripts/i18n-extract --check`: `locales/messages.pot` and each catalog
  match what extraction produces, so no string reaches a release without
  being extracted.
- `msgfmt -c` passes on every `.po`.

The `test` job runs `aximar-core/tests/catalog.rs`:
- each translation keeps its msgid's placeholder names (a plural form may
  leave one out, as in "un archivo"), and stays within any `max-length:N`
  in its note or flags; untranslated and fuzzy entries are skipped;
- Rust-side text holds no literal braces.

`aximar-core/tests/maxima_messages.rs` checks that every message the code
can produce is in the template with the same English, that every
explanation entry in the template is one the code produces, and that
`docs/maxima-messages.md` matches what `scripts/i18n-extract` generates
from the template.

## Fragility

| Risk | What happens | Guard |
|---|---|---|
| Maxima's language leaks in from the environment | Errors pass as results; the debugger hangs | `LANGUAGE=en` on every launch; `tests/spanish_locale.rs` runs with all four variables set to Spanish. Anything new that starts Maxima must go through `MaximaProcess`. |
| Maxima rewords an English message Aximar matches | Errors pass as results, or explanations disappear | Aximar's Maxima tests. They're ignored by default because CI has no Maxima, so run them with `--ignored` before each release. |
| Maxima's translators fill in strings Aximar parses, such as the `asksign` question | Nothing, while the pin holds | The pin |
| A Maxima release changes what the wrapper relies on: `errormsg()`, `$error`'s layout, `intl::*locale*`, `intl:dgettext` | No tagged line: the user sees English | The wrapper ignores its own errors; `tests/translated_errors.rs` |
| A Maxima build or package without the catalogs | English only, without any warning | Report which languages the installed Maxima has (planned); check the Docker image's Ubuntu package |
| Partial or poor translations: Spanish drops `matrix:` from one message | The user sees English, or a weaker message | Per-message fallback; fixes go upstream |
| A string added without extraction | English in every language | The CI check on `messages.pot` |
| A translation breaks a placeholder | A missing or garbled value in the window | The placeholder test; `msgfmt -c` |
| The two extractors disagree on placeholder style | `msgfmt -c` or Lingui rejects a string | Named braces only; no ICU syntax in Rust strings |
| A language falls behind | English for new text | Per-message fallback; fuzzy entries for changed text; a per-release list for translators |
| User code prints `__AXIMAR_MSG__...` | The parser takes it as a translation | Accepted, as for Aximar's other tags |
| The help index ages against the English manual | Missing or stale summaries in that language | Regenerate with each Maxima update; fall back to English per symbol |
| Saved notebooks | A reopened notebook shows the English error until the cell runs again | Accepted: files hold Maxima's own output |

## Process

### Adding a language

1. Check what Maxima has: the message catalog's and the manual's coverage
   (see the table above).
2. Run `scripts/i18n-add-language <lang>`, which makes
   `locales/<lang>.po` with `msginit` (filling in the language's
   `Plural-Forms`) and then `msgmerge --compendium` against Maxima's
   catalog for that language, if it has one.
3. A translator fills it in (below).
4. Generate the help index for the language, if Maxima has a manual in it.
5. Add the language to `locales` in `lingui.config.ts`. The setting lists
   every catalog in `locales/`, and the gallery script's `LANGUAGES`
   takes it too.

### Translating

1. Open `locales/<lang>.po` in Poedit (or Lokalize, or OmegaT). Each entry
   shows the English, its context, a comment, its source and its screen.
   The gallery shows it in Storybook, in any language.
2. Keep a pre-release Aximar open with the file loaded through "Load
   translation file...". Each save updates the window.
3. Send the file back, or open a pull request. CI checks placeholders and
   lengths.
4. A second speaker of the language reviews, and someone runs through the
   app in that language before release.

### Keeping it up to date

- **Aximar's text.** A change that adds or changes text runs
  `scripts/i18n-extract` in the same pull request, and CI fails if it
  didn't. Before each release, a script lists each language's untranslated
  and fuzzy entries in a GitHub issue for its translators.
- **Maxima's messages and manual.** Fixes and new translations go to
  Maxima upstream: `locale/<lang>.po` and `doc/info/<lang>/` in Maxima's
  repository, through its patch tracker or mailing list. Aximar's users get
  them with their next Maxima. We ask Spanish users who meet an
  untranslated or poor message to submit it there.
- **Syntax errors.** Maxima's parser prints most of its messages without a
  catalog lookup, so translating them upstream would first need a patch
  that adds one. Until then Aximar's catalog holds them.
- **Roles.** The maintainers own the English text, the template and the
  tooling. Each language's contributors own its file, and a second speaker
  reviews where possible.

### Tools for translators

No hosted service is needed: the repository, a desktop editor and CI cover
context, checks, screenshots and review. If more translators join and want
a web interface, Hosted Weblate (free for open-source projects) or a
self-hosted Weblate can work on the same files through git, with nothing to
migrate. Comments already use Weblate's flag syntax.

Aximar's catalogs ship with Aximar's releases, and Maxima's with Maxima's.
Neither copies the other.
