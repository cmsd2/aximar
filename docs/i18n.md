# Localisation

How Aximar shows its text, Maxima's messages and the help in the user's
language: where each piece of text comes from, where its translations come
from, how they reach the window, who keeps them up to date, and what can
break. It starts from [#44](https://github.com/cmsd2/aximar/issues/44), a
request for Spanish for a student pilot.

## Principles

- **Maxima runs in English.** Aximar reads Maxima's messages to tell when
  an evaluation failed, so the language between Maxima and Aximar never
  changes. Translation happens where Aximar draws text.
- **Translations come from whoever owns the text.** Aximar translates its
  own text. Maxima's messages and manual come from Maxima's translators,
  and Aximar reads them from the installed Maxima instead of copying them.
- **A missing translation falls back to English, one message at a time.**
  A partly translated language is still useful.
- **The language is an Aximar setting**, defaulting to the system's.
  Aximar never passes it to Maxima's environment.
- **Results and user output stay as written.** Aximar translates text about
  a computation, never the computation: `print` output, results and
  function names stay as Maxima gives them.

## Where text comes from

| Text | Produced by | Example | Translations come from | How they reach the window | Status |
|---|---|---|---|---|---|
| Window UI | React components in `src/components` | "Show raw error" | Aximar's catalog | Bundled with the window | Planned |
| Native menus | `src-tauri/src/menu.rs` | "Save As..." | Aximar's catalog | Read by Rust when the menu is built | Planned |
| Aximar's error explanations, suggestion chips, the `asksign` notice | `aximar-core`: `errors.rs`, `suggestions/` | "Division by Zero" | Aximar's catalog | Rust sends a key and parameters; the window looks them up | Planned |
| Maxima's runtime errors | Maxima's `merror` | `expt: undefined: 0 to a negative exponent.` | Maxima's catalog, `locale/<lang>.po`, installed as `maxima.mo` | Maxima translates at error time (`ax_messages.lisp`); the parser lifts it into `error_translated` | Prototype, [#108](https://github.com/cmsd2/aximar/pull/108) |
| Maxima's syntax errors | Maxima's parser (`mread-synerr`) | `incorrect syntax: Missing )` | Aximar's catalog: Maxima translates only 2 of its 19 patterns | The parser matches the English pattern | Planned |
| Lisp errors | The Lisp Maxima runs on | `Maxima encountered a Lisp error: ...` | None: the condition text comes from the Lisp | Aximar's explanation only | Planned |
| Maxima's warnings and info | Maxima's `mtell` and `mwarning` (about 140 calls in the core) | `rat: replaced 0.5 by 1/2 = 0.5` | Aximar's catalog for the common ones, at first | The parser matches the English pattern | Open |
| Maxima's questions | Maxima's `asksign` | `Is x positive, negative or zero?` | Not shown: Aximar answers the question itself | Aximar's notice, from its catalog | Planned |
| Help summaries | `core-doc-index.json`, built by catalog-gen from Maxima's manual | The summary of `integrate` | Maxima's translated manual, `doc/info/<lang>` | catalog-gen builds one index per language; Aximar embeds them | Planned |
| Full help text | The `maxima-core-docs` package | The body of `integrate`'s entry | None yet | | Open |
| Results, `print` output, function names | The user's code | `x^2/2` | Never translated | | |
| aximar-mcp, maxima-dap, the VS Code extension | The tools | | English | | Out of scope |

aximar-mcp's readers are AI tools, which work best in English. The VS Code
extension would use VS Code's own localisation (`vscode.l10n`) if it ever
needs translating.

## Data flow

### A failed cell

```
cell input
  │
  ▼
Maxima, started with LANGUAGE=en                       (process.rs)
  │  merror("~:@M: wrong number of arguments.", diff)
  │  └─ errormsg(), wrapped by ax_messages.lisp
  │       ├─ prints  diff: wrong number of arguments.
  │       └─ looks the pattern up for ax__language = "es",
  │          formats it, prints
  │          __AXIMAR_MSG__diff: número de argumentos equivocados.__AXIMAR_MSG_END__
  ▼
stdout and stderr lines                                (MaximaProcess)
  │
  ▼
legacy parser                                          (legacy/parser.rs)
  ├─ English markers   → is_error, error
  ├─ errors.rs         → error_info (title, explanation: keys, once the catalog exists)
  └─ tagged line       → error_translated
  ▼
CellOutput, synced to the window
  ▼
EnhancedErrorOutput: the translation, with "Show original" for the English,
under Aximar's explanation when it has one
```

The tagged line comes out at error time, before Maxima shows any prompt,
so this works at the top level, inside `errcatch` and in the debugger. A
query after the error would only work at the normal prompt.

### The language

```
Aximar setting (default: the system language)
  ├─ window: picks the catalog for UI text, explanations and menus
  ├─ session start: ax__language: "es"$           (prototype: AXIMAR_LANGUAGE)
  └─ help: picks the help index for that language
```

Changing the setting while a session runs sets `ax__language` with one
evaluation, which Aximar can do whenever Maxima is idle.

### Build time

```
Maxima source: doc/info/<lang>/maxima.texi
  └─ catalog-gen  →  core-doc-index.<lang>.json, embedded in aximar-core

Aximar source: the English catalog
  └─ translators  →  one catalog file per language, bundled with the window
```

Maxima's message catalogs aren't part of Aximar's build: Maxima installs
them, and Maxima reads them at run time.

## Technical design

### English between Maxima and Aximar

Maxima picks its language from the first of `LANGUAGE`, `LC_ALL`,
`LC_MESSAGES` and `LANG` that's set (`setlocale` in Maxima's
`src/intl.lisp`), using only the first two letters. Aximar sets
`LANGUAGE=en` on the local, Docker and WSL launches (`MAXIMA_LANGUAGE` in
`process.rs`, [#107](https://github.com/cmsd2/aximar/pull/107)).

Aximar sets only `LANGUAGE` on the local launch: changing `LC_ALL` would
also change the C library's locale, and with it the character set SBCL
uses for UTF-8. Docker and WSL also set `LANG` and `LC_ALL` to
`en_US.UTF-8`, as before.

Without the pin, a Spanish system language broke Aximar:
- a failed cell came back as the result before it;
- Run All went past errors;
- the debugger hung on a syntax error.

### Maxima's runtime errors: `ax_messages.lisp`

`merror` stores each error in `$error` as its message pattern and
arguments, such as `("~:@M: wrong number of arguments." diff)`. Under
English, the pattern is exactly the key in Maxima's catalog. Every branch
of `merror` prints through `errormsg()`.

The wrapper:
1. calls the original `errormsg()`, so the English message prints as
   before;
2. looks the pattern up with Maxima's own `intl:dgettext`, with
   `intl::*locale*` bound to `ax__language` for that one lookup;
3. if the catalog has a translation, calls the original `errormsg()` again
   with the translated pattern, capturing its output, so Maxima formats
   the arguments as usual;
4. prints the result as one tagged line, newlines as `\n` and backslashes
   doubled.

It prints nothing when `ax__language` is empty, when the catalog has no
translation, or when anything in steps 2 to 4 fails.

Aximar sends the file at session start as one `:lisp` line, before the
plotting init's evaluation, which reads the line's reply. Sent with no
evaluation after it, the reply leaks into the first cell's output.

The parser lifts the tagged line into `error_translated` and keeps it only
when the evaluation failed. `errcatch` prints the messages of errors it
catches, but those cells succeed. When one cell prints several messages,
the last belongs to the error that stopped it.

### Aximar's own text

One catalog file per language. The choice of library is open:

| Option | Window | Rust (menus) | Translators edit | Trade-off |
|---|---|---|---|---|
| i18next | `i18next`, `react-i18next` | reads the same JSON with `serde_json` | JSON | Largest ecosystem; plurals follow i18next's conventions |
| Fluent | `@fluent/bundle` | `fluent-bundle`, `i18n-embed-fl` | `.ftl` | Grammar such as plurals lives in the translation; `@fluent/react` hasn't had a release since 2023 |
| gettext | `@lingui/core` | `rspolib` | `.po`, in Poedit | The format Maxima's translators use; needs an extract and compile step |

`aximar-core` returns a key and parameters instead of English sentences,
so the window holds the only copy of each translation. The suggestion
chips, `errors.rs` and the `asksign` notice change this way. The curated
translations of Maxima's syntax errors and warnings also live in this
catalog, keyed on Maxima's English pattern.

### Help

catalog-gen runs once per language on `doc/info/<lang>/maxima.texi` and
writes one index per language. Aximar looks a symbol up in the user's
language first, then in English. Search covers both, since students may
search in either.

## Fragility

| Risk | What happens | Guard |
|---|---|---|
| Maxima's language leaks in from the environment | Errors pass as results; the debugger hangs | `LANGUAGE=en` on every launch; `tests/spanish_locale.rs` runs with all four variables set to Spanish. Anything new that starts Maxima must go through `MaximaProcess`. |
| Maxima rewords an English message Aximar matches | Errors pass as results, or explanations disappear | Aximar's Maxima tests. They're ignored by default because CI has no Maxima, so run them with `--ignored` before each release. |
| Maxima's translators fill in strings Aximar parses, such as the `asksign` question | Nothing, while the pin holds | The pin |
| A Maxima release changes what the wrapper relies on: `errormsg()`, `$error`'s layout, `intl::*locale*`, `intl:dgettext` | No tagged line: the user sees English | The wrapper ignores its own errors; `tests/translated_errors.rs` |
| A Maxima build or package without the catalogs | English only, without any warning | Report which languages the installed Maxima has (planned); check the Docker image's Ubuntu package |
| Partial or poor translations: Spanish drops `matrix:` from one message | The user sees English, or a weaker message | Per-message fallback; fixes go upstream |
| A key used in code but missing from the English catalog | Raw keys in the window | A test that every key used exists in the English catalog (planned) |
| A language's catalog falls behind | English for the new text | Per-key fallback; a per-release list of untranslated keys |
| User code prints `__AXIMAR_MSG__...` | The parser takes it as a translation | Accepted, as for Aximar's other tags |
| The help index ages against the English manual | Missing or stale summaries in that language | Regenerate with each Maxima update; fall back to English per symbol |
| Saved notebooks | A reopened notebook shows the English error until the cell runs again | Accepted: files hold Maxima's own output |

## Process

### Adding a language

1. Check what Maxima has: the message catalog's coverage and the manual's
   (see the table above).
2. A contributor copies the English catalog to the new language and
   translates it, in a pull request.
3. Generate the help index for the language, if Maxima has a manual in it.
4. Add the language to the setting's list.

### Keeping it up to date

- **Aximar's text.** A change that adds window text adds its English
  key in the same pull request, and review checks it. Before each release,
  list each language's untranslated keys and ask its translators. If
  contributions grow, a hosted tool such as Weblate can take over.
- **Maxima's messages and manual.** Fixes and new translations go to
  Maxima upstream: `locale/<lang>.po` and `doc/info/<lang>/` in Maxima's
  repository, through its patch tracker or mailing list. Aximar's users get
  them with their next Maxima. We ask Spanish users who meet an
  untranslated or poor message to submit it there.
- **Syntax errors.** Maxima's parser doesn't pass most of its messages to
  gettext, so translating them upstream would first need a patch that
  does. Until then Aximar's catalog holds them.
- **Roles.** The maintainers own the English catalog and the structure.
  Each language's contributors own its file, and a second speaker of the
  language reviews where possible.

Aximar's catalogs ship with Aximar's releases, and Maxima's with Maxima's.
Neither copies the other.

## Roadmap

1. Keep Maxima in English: [#107](https://github.com/cmsd2/aximar/pull/107).
2. Maxima's runtime errors through `ax_messages.lisp`: prototype in
   [#108](https://github.com/cmsd2/aximar/pull/108).
3. The language setting, and the catalog for the window, the menus and
   Aximar's explanations, with Maxima's syntax errors in it. This gives
   #44's translators something to work on.
4. Spanish help summaries from catalog-gen.
5. Maxima's common warnings, curated in the catalog.
